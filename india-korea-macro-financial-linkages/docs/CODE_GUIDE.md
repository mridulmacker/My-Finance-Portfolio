# MATLAB code guide

## What is included

The `code/` directory contains the 41 scripts supplied with this portfolio project. It preserves the research workflow, including exploratory checks and later corrections. Script numbers are historical labels, and the archive does not contain every number in the sequence. The dissertation PDF is the source for the submitted findings; this archive has not been rerun against those findings.

The code is written for MATLAB with the Econometrics Toolbox (`varm`, `vecm`, `jcitest`, `jcontest`, `irf`, `fevd`, `gctest`, `adftest`, `kpsstest`, `archtest`, `lbqtest`). Several diagnostic calculations also use functions from the Statistics and Machine Learning Toolbox, such as `chi2cdf`, `fcdf` and distributional tests. No minimum MATLAB release or complete toolbox combination has been certified for the archive.

## Local input setup

1. Obtain and assemble the data described in [DATA.md](DATA.md).
2. Place your local `master_dataset.csv` in `code/`. It is intentionally ignored by Git.
3. For the financial-openness chart, also place `kaopen_2023.xls` in `code/`.
4. Open MATLAB and set **Current Folder** to this project's `code/` directory.
5. Work on a local copy: scripts beginning with `clear` reset the workspace, and several scripts overwrite `master_dataset_transformed.mat` or earlier result files.

## Preparation and entry points

The following are individual starting points, not a tested automated batch runner:

```matlab
% Current Folder must be this project's code/ directory.
step1_load_data             % Inspect your local raw CSV.
step2_stationarity          % ADF checks and initial transformed dataset.
step20_tidy_rebuild         % Rebuild transformed data INCLUDING T-bill differences.

% Choose analysis modules after preparation:
step24_cointegration_test   % Johansen checks across eight specifications.
step33_diagnostic_fix_script % Later comparison of normalised VAR/VECM FEVDs.
step31_weak_exo_tests       % Weak-exogeneity restrictions with rank caveats.
step26_granger_toda_yamamoto % Predictive relationships in levels.
recheck                    % Date-aligned COVID dummies and pre-pandemic FEVD.
```

`step2_stationarity.m` does not create `d_us3mtbills`. Run `step20_tidy_rebuild.m` after it before running the five-variable analysis modules. `step11_india_c1_tbill.m` also adds this series, but additionally estimates an India model.

## Version and interpretation notes

- `step25_vecm.m` retains the earlier India M3 rank-two specification. The separate rank-one correction is in `step30_indiac4_rank_correction.m`; `step31_weak_exo_tests.m` and `step33_diagnostic_fix_script.m` also use rank one. Do not combine the earlier and corrected outputs as if they were the same model.
- Some earlier FEVD scripts display raw generalised contributions. The later comparison script displays both raw and normalised values. Compare dissertation tables with the appropriate normalised measure.
- `recheck.m` aligns dates separately with each specification's missing-value filter, uses March–May 2020 impulse dummies, and compares with a sample ending before March 2020. Supply the actual dates rather than relying on its fallback calendar. `covid_dummy.m` is a separate earlier outlier-based check with an approximate joint statistic from marginal standard errors; do not substitute it for `recheck.m`.
- `graph2.m` estimates a levels VAR for its illustrative plots. It does not regenerate all VECM or VAR-in-differences results and does not plot confidence intervals. Confirm response/shock indexing against the installed MATLAB release before reusing it.
- The bootstrap script uses IID residual resampling. Its uncertainty estimates should not be described as automatically robust to residual ARCH effects.
- `stw.m` is byte-for-byte identical to `step10_korea_d4.m`. `results5.1.m` is byte-for-byte identical to `step32_results_51.m`. Both historical aliases are retained for traceability; use the descriptive step filenames.
- Some header comments refer to older step numbers or table numbers. Use this guide and the dissertation to identify their purpose.

Publication checks covered file integrity, documentation links, input dependencies and PDF preparation. MATLAB execution and numerical agreement with the dissertation were not tested in this publication workflow.
